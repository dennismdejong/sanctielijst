# Login (auth) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Login met gebruikersnaam/wachtwoord en rollen (`admin`/`analist`/`viewer`) via een ondertekende sessie-cookie. De app kan hiermee niet-publiek worden; de audit-log legt de ingelogde gebruiker vast, watchlists worden per gebruiker gescope (nu cookie-key, straks `user_id`), en admin-functionaliteit (audit-log, gebruikersbeheer) wordt rolgebonden.

**Architecture:** `app/auth.py` beheert gebruikers (`data/auth.sqlite`, wachtwoorden met **bcrypt**) en sessies (ondertekende cookie met **itsdangerous**, `AUTH_SECRET`). FastAPI-dependencies (`get_current_user`, `require_role`) zetten de huidige gebruiker. `AUTH_REQUIRED` (env, default `0`) bepaalt of zoek/export-zoeken een login vereisen — zo blijft de huidige publieke deploy achterwaarts compatibel. `GET /api/auth/*` is altijd publiek. De audit-log (Fase 1) krijgt een `user`-kolom: ingelogd → gebruikersnaam; anoniem → `null` (alleen IP).

**Tech Stack:** Python 3.11, nieuwe dependencies **`bcrypt`** en **`itsdangerous`** (pin op latest); stdlib `sqlite3`/`secrets`; bestaande FastAPI.

## Global Constraints

- Gebruikers: `data/auth.sqlite` (env `AUTH_DB`), tabel `users(id TEXT PK, username TEXT UNIQUE, password_hash TEXT, role TEXT NOT NULL CHECK(role IN ('admin','analist','viewer')), created_at TEXT)`. Wachtwoorden uitsluitend als bcrypt-hash.
- Sessie: ondertekende cookie `session` (itsdangerous `TimedSerializer`, max_age bv. 12 uur, `HttpOnly`, `SameSite=lax`, `Secure` achter HTTPS) met payload `{user_id, role}`; `AUTH_SECRET` env verplicht als auth actief is.
- Rollen: `admin` = alles (incl. audit-log + gebruikersbeheer), `analist` = zoeken + export + batch, `viewer` = alleen zoeken.
- `AUTH_REQUIRED` env (`0`|`1`, default `0`): bij `1` vereisen `/api/search*`, export en batch een ingelogde analist/viewer; bij `0` blijft alles publiek (backward compatible). `/api/auth/*`, `/api/health`, `/api/status` altijd publiek.
- Audit (Fase 1): `audit_log` krijgt een nullable `user`-kolom; de route vult die uit de sessie (dependency), anoniem = `null`. Audit-weergave vereist rol `admin` (in plaats van/in aanvulling op `AUDIT_ADMIN_TOKEN`).
- Watchlists (Fase 4): `owner` = `user_id` als ingelogd, anders de anonieme cookie-key (fallback).
- Gebruikersaanmaak: alleen via `admin`-endpoint of CLI `scripts/create_user.py` (geen zelf-registratie; geschikt voor een screeningstool).
- UI-taal Nederlands; identifiers Engels. Geen code-commentaar tenzij niet-voor-de-hand liggend.
- STAGE nooit via `git add .`; alleen eigen bestanden. Testsuite: `.venv/bin/python -m pytest -v`.

### Task 1: auth-module

**Files:**
- Modify: `requirements.txt`
- Create: `app/auth.py`
- Test: `tests/test_auth.py`

**Interfaces:**
- Produces:
  - `default_auth_db() -> Path` — `AUTH_DB` of `data/auth.sqlite`.
  - `init_auth_db(db_path)` — schema (idempotent).
  - `hash_password(password: str) -> str` (bcrypt), `verify_password(password, password_hash) -> bool`.
  - `create_user(db_path, username, password, role) -> dict` (raises ValueError bij dubbele username/ongeldige role).
  - `verify_login(db_path, username, password) -> dict | None` — gebruiker of None.
  - `create_session(user: dict, secret: str, max_age=43200) -> str` (itsdangerous cookie-waarde), `verify_session(token: str | None, secret: str) -> dict | None`.
  - `current_user(request, db_path, secret) -> dict | None` — leest de cookie en retourneert `{user_id, username, role}`.

**Tests:** hashen/verifiëren; create_user (duplicate → ValueError, rol-validatie); verify_login (juist/onjuist wachtwoord); session round-trip + verlopen/geknoeide token → None; `current_user` uit een request-object.

### Task 2: endpoints + dependencies + gating

**Files:**
- Modify: `app/main.py`
- Test: `tests/test_main.py`

**Interfaces:**
- Consumes: `app.auth`.
- Produces:
  - `AUTH_SECRET`/`AUTH_DB`/`AUTH_REQUIRED` uit env (met default; bij `AUTH_REQUIRED=1` zonder `AUTH_SECRET` → startup-fout).
  - `get_current_user(request)` dependency → `current_user`; `require_role(*roles)` dependency → 401/403.
  - `POST /api/auth/login` (JSON `{username, password}`) → set-cookie `session`; `POST /api/auth/logout` → clear; `GET /api/auth/me` → `{username, role}` of 401.
  - `POST /api/auth/users` (admin only, JSON `{username, password, role}`).
  - Gating: als `AUTH_REQUIRED=1` vereisen `search`, `search_export` en batch `require_role("analist","viewer")`; audit-log admin-only.
  - Audit-integratie: `audit.log_event` krijgt `user` (uit sessie of `None`).

**Tests:** login-juist/onjuist; cookie round-trip via TestClient; `me`; `require_role` 401/403; `AUTH_REQUIRED=1` blokkeert search zonder login en staat toe met login; users-endpoint alleen admin; audit-event bevat `user` bij ingelogd en `None` bij anoniem.

### Task 3: CLI + UI + docs

**Files:**
- Create: `scripts/create_user.py`
- Modify: `static/index.html`, `static/app.js`, `static/style.css`, `README.md`, `.env.example`

**Interfaces:**
- Produces:
  - `scripts/create_user.py` (argparse: `--username --password --role`) — bootstrapt de eerste admin; leest `AUTH_DB`.
  - Login-formulier (modaal of sectie) + uitlog-knop; `fetch` met `credentials: "same-origin"`; bij 401 de login tonen (alleen relevant als `AUTH_REQUIRED=1`).
  - `.env.example`: `AUTH_SECRET=`, `AUTH_DB=`, `AUTH_REQUIRED=0`.
  - README: auth-sectie (rollen, users aanmaken, `AUTH_REQUIRED`, audit-gebruiker).

**Verificatie:** `node --check`, volledige suite groen, handmatige test (login → audit toont user; logout → anoniem).
