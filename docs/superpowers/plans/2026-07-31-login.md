# Login (auth) Implementation Plan — eigen login én IdP (OIDC)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Login met gebruikersnaam/wachtwoord (eigen gebruikers) **én** een externe Identity Provider via **OpenID Connect (OIDC)** — na succesvolle authenticatie geeft de app altijd haar **eigen ondertekende sessie-cookie** uit. Rollen (`admin`/`analist`/`viewer`) en alle afhankelijke logica (audit-log `user`, watchlist-`owner`, gating) werken identiek, ongeacht of de gebruiker lokaal of via het IdP is ingelogd.

**Architecture:** `app/auth.py` abstraheert twee providers achter één `authenticate()`-interface:
- **Lokaal:** username/password → bcrypt-controle tegen `data/auth.sqlite` (tabel `users`).
- **OIDC:** autorization-code-flow (redirect naar de IdP, `/api/auth/callback` wisselt de code in, `userinfo` → lokale user-record o.b.v. `idp`+`idp_subject`).
Na succesvolle auth maakt de app een `session`-cookie (itsdangerous `TimedSerializer`) met `{user_id, role}`. De rest van de app (FastAPI-dependencies `get_current_user`/`require_role`, audit, watchlists) leest alleen die cookie — provider-agnostisch. `AUTH_REQUIRED` (default `0`) bepaalt of zoek/export/batch een login vereisen.

**Tech Stack:** Python 3.11, nieuwe dependencies **`bcrypt`**, **`itsdangerous`**, **`authlib`** (OIDC-client; pin op latest); bestaande FastAPI/httpx; stdlib `sqlite3`/`secrets`.

## Global Constraints

- Gebruikers: `data/auth.sqlite` (env `AUTH_DB`), tabel `users(id TEXT PK, username TEXT UNIQUE, password_hash TEXT, role TEXT NOT NULL CHECK(role IN ('admin','analist','viewer')), idp TEXT, idp_subject TEXT UNIQUE, created_at TEXT)`.
  - Lokale gebruiker: `idp` NULL, `password_hash` gevuld.
  - IdP-gebruiker: `idp` = provider-naam (bv. `keycloak`), `idp_subject` = subject uit userinfo; `password_hash` NULL.
- Sessie: ondertekende cookie `session` (itsdangerous, max_age 12u, `HttpOnly`, `SameSite=lax`, `Secure` achter HTTPS), payload `{user_id, role}`; `AUTH_SECRET` env verplicht als auth actief is.
- Config (env): `AUTH_REQUIRED` (`0`|`1`, default `0`), `AUTH_LOCAL_ENABLED` (default `1`), `AUTH_OIDC_ENABLED` (default `0`), `AUTH_OIDC_ISSUER`, `AUTH_OIDC_CLIENT_ID`, `AUTH_OIDC_CLIENT_SECRET`, `AUTH_OIDC_REDIRECT_URI`, `AUTH_OIDC_SCOPE` (default `openid profile email`). `AUTH_OIDC_ENABLED=1` zonder issuer/client-id/redirect → startup-fout.
- Rollen: `admin` = alles (incl. audit + gebruikersbeheer), `analist` = zoeken + export + batch, `viewer` = alleen zoeken. Rol wordt lokaal toegekend (kolom `role`); optioneel later: rol uit een IdP-`roles`-claim overnemen (buiten scope voor v1, noteer als uitbreiding).
- Endpoints: `GET /api/auth/login` (bij OIDC-enabled: redirect naar IdP; anders local-form), `POST /api/auth/login` (JSON `{username,password}`, lokaal), `GET /api/auth/callback` (OIDC redirect_uri), `POST /api/auth/logout`, `GET /api/auth/me`. Deze zijn altijd publiek.
- Nieuwe IdP-gebruiker (subject onbekend): automatisch aanmaken met rol `viewer` (configurable default `AUTH_OIDC_DEFAULT_ROLE`, default `viewer`); beheer kan de rol later aanpassen.
- Gating: bij `AUTH_REQUIRED=1` vereisen `search`, `search_export`, batch `require_role("analist","viewer")`; audit-log admin-only (rol `admin` óf `AUDIT_ADMIN_TOKEN`).
- Audit (Fase 1): `user`-kolom gevuld uit de sessie (provider-agnostisch); anoniem = `null`.
- Watchlists (Fase 4): `owner` = `user_id` bij ingelogd, anders cookie-key.
- UI-taal Nederlands; identifiers Engels. Geen code-commentaar tenzij niet-voor-de-hand liggend.
- STAGE nooit via `git add .`; alleen eigen bestanden. Testsuite: `.venv/bin/python -m pytest -v`.

### Task 1: auth-module (lokaal + sessie)

**Files:**
- Modify: `requirements.txt` (bcrypt, itsdangerous, authlib)
- Create: `app/auth.py`
- Test: `tests/test_auth.py`

**Interfaces:**
- Produces:
  - `default_auth_db() -> Path` — `AUTH_DB` of `data/auth.sqlite`; `init_auth_db(db_path)` — schema (idempotent).
  - `hash_password(password) -> str` (bcrypt); `verify_password(password, hash) -> bool`.
  - `create_user(db_path, username, password=None, role="viewer", idp=None, idp_subject=None) -> dict` (uniekheid per username én idp_subject; ValueError bij conflict/ongeldige rol).
  - `find_by_credentials(db_path, username, password) -> dict | None` (lokale login).
  - `find_or_create_idp_user(db_path, idp, idp_subject, default_role="viewer") -> dict`.
  - `create_session(user: dict, secret, max_age=43200) -> str`; `verify_session(token, secret) -> dict | None`.
  - `current_user(request, db_path, secret) -> dict | None`.

**Tests:** hashen/verifiëren; create_user lokaal + IdP (conflicten); find_by_credentials; find_or_create_idp_user (bestaand/nieuw); session round-trip + verlopen/geknoeid; current_user uit request.

### Task 2: OIDC-provider

**Files:**
- Modify: `app/auth.py`
- Test: `tests/test_auth.py`

**Interfaces:**
- Produces:
  - `oidc_config() -> dict | None` — uit env (`AUTH_OIDC_ENABLED` etc.); `None` als uitgeschakeld.
  - `oidc_client(config) -> authlib.integrations.httpx_client.AsyncOAuth2Client` (client_id/secret; discovery via `issuer/.well-known/openid-configuration`).
  - `oidc_authorize_url(client, state) -> (url, state)`; `oidc_exchange(client, code, state_secret) -> dict` (token → userinfo).
  - In de routes: state-verificatie (itsdangerous `URLSafeTimedSerializer` voor de OIDC-state met korte TTL), userinfo-subject → `find_or_create_idp_user`.

**Tests:** config parsing (aan/uit + validatie-fout bij incomplete config); authorize-url bouwen; exchange met gemockte IdP (httpx mock) → subject; state-verificatie (ongeldig/verlopen → 400).

### Task 3: endpoints + gating

**Files:**
- Modify: `app/main.py`
- Test: `tests/test_main.py`

**Interfaces:**
- Consumes: `app.auth`.
- Produces:
  - `AUTH_SECRET`/`AUTH_DB`/`AUTH_REQUIRED`/`AUTH_OIDC_*` uit env; validatie bij startup.
  - `get_current_user(request)` / `require_role(*roles)` dependencies.
  - `GET /api/auth/login`: OIDC-enabled → `RedirectResponse` naar IdP (met state); anders 200/JSON (UI toont formulier). `POST /api/auth/login` (lokaal) → set-cookie. `GET /api/auth/callback` → code exchange + set-cookie + redirect naar `/`. `POST /api/auth/logout` → clear-cookie. `GET /api/auth/me`.
  - `POST /api/auth/users` (admin only): lokale gebruiker of IdP-toewijzing (`{username, password?, role, idp?, idp_subject?}`).
  - Gating (bij `AUTH_REQUIRED=1`) + audit-`user`-invulling.

**Tests:** lokale login (set-cookie/me/logout); IdP-flow met gemockte discovery+token+userinfo → set-cookie; state-fouten; require_role 401/403; AUTH_REQUIRED-gating; users-endpoint admin-only; audit-event `user` gevuld bij login en `None` bij anoniem.

### Task 4: CLI + UI + docs

**Files:**
- Create: `scripts/create_user.py`

**Interfaces:**

  - UI: login-sectie met lokaal formulier én (indien `AUTH_OIDC_ENABLED`) een "Login met IdP"-knop (redirect naar `/api/auth/login`); uitlog-knop; `fetch` met `credentials:"same-origin"`.
  - `.env.example`: alle `AUTH_*`-vars.
  - README: eigen login + IdP-config (issuer/client/redirect, voorbeeld Keycloak/Authentik/Google), rollen, `AUTH_REQUIRED`.

**Verificatie:** `node --check`, volledige suite groen, handmatige test (lokaal login → audit `user`; IdP-flow indien een IdP beschikbaar is).
