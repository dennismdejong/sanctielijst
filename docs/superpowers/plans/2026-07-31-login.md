# Login (auth) Implementation Plan — eigen login én Microsoft Entra ID

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Login met gebruikersnaam/wachtwoord (eigen gebruikers) **én** **Microsoft Entra ID** als Identity Provider (via OpenID Connect) — na succesvolle authenticatie geeft de app altijd haar **eigen ondertekende sessie-cookie** uit. Rollen (`admin`/`analist`/`viewer`) en alle afhankelijke logica (audit-log `user`, watchlist-`owner`, gating) werken identiek, ongeacht of de gebruiker lokaal of via Entra is ingelogd.

**Architecture:** `app/auth.py` abstraheert twee providers achter één `authenticate()`-interface:
- **Lokaal:** username/password → bcrypt-controle tegen `data/auth.sqlite` (tabel `users`).
- **Entra ID:** OIDC authorization-code-flow (+PKCE) tegen de Entra v2.0-endpoints (`https://login.microsoftonline.com/{tenant}/v2.0`); `/api/auth/callback` wisselt de code in, `userinfo`-`sub` → lokale user-record o.b.v. `idp`+`idp_subject`.
Na succesvolle auth maakt de app een `session`-cookie (itsdangerous `TimedSerializer`) met `{user_id, role}`. De rest van de app (FastAPI-dependencies `get_current_user`/`require_role`, audit, watchlists) leest alleen die cookie — provider-agnostisch. `AUTH_REQUIRED` (default `0`) bepaalt of zoek/export/batch een login vereisen. Andere IdP's (Keycloak, Google, ...) zijn bewust **niet** ondersteund (alleen Entra, v1).

**Tech Stack:** Python 3.11, nieuwe dependencies **`bcrypt`**, **`itsdangerous`**, **`authlib`** (OIDC-client voor Entra; pin op latest); bestaande FastAPI/httpx; stdlib `sqlite3`/`secrets`.

## Global Constraints

- Gebruikers: `data/auth.sqlite` (env `AUTH_DB`), tabel `users(id TEXT PK, username TEXT UNIQUE, password_hash TEXT, role TEXT NOT NULL CHECK(role IN ('admin','analist','viewer')), idp TEXT, idp_subject TEXT UNIQUE, created_at TEXT)`.
  - Lokale gebruiker: `idp` NULL, `password_hash` gevuld.
  - Entra-gebruiker: `idp = 'entra'`, `idp_subject` = het Entra-`sub`-claim (immutable); `password_hash` NULL; `username` = `preferred_username`/`email` (fallback).
- Sessie: ondertekende cookie `session` (itsdangerous, max_age 12u, `HttpOnly`, `SameSite=lax`, `Secure` achter HTTPS), payload `{user_id, role}`; `AUTH_SECRET` env verplicht als auth actief is.
- Config (env): `AUTH_REQUIRED` (`0`|`1`, default `0`), `AUTH_LOCAL_ENABLED` (default `1`), `AUTH_ENTRA_ENABLED` (default `0`), `AUTH_ENTRA_TENANT` (tenant-id of `organizations`), `AUTH_ENTRA_CLIENT_ID`, `AUTH_ENTRA_CLIENT_SECRET`, `AUTH_ENTRA_REDIRECT_URI` (bv. `https://sanctielijst.brakketak.nl/api/auth/callback`), `AUTH_ENTRA_SCOPE` (default `openid profile email`). `AUTH_ENTRA_ENABLED=1` zonder tenant/client-id/secret/redirect → startup-fout.
- Entra-v2.0: OIDC-discovery op `https://login.microsoftonline.com/{tenant}/v2.0/.well-known/openid-configuration`; authorization-code-flow met **PKCE** (code_verifier/challenge) + client_secret. Redirect-URI moet in de Entra-app-registratie staan.
- Rollen: `admin` = alles (incl. audit + gebruikersbeheer), `analist` = zoeken + export + batch, `viewer` = alleen zoeken. Rol wordt lokaal toegekend (kolom `role`); Entra-app-roles/groepen niet overnemen in v1 (noteer als uitbreiding).
- Endpoints: `GET /api/auth/login` (Entra-enabled → redirect naar Entra met PKCE+state; anders local-form), `POST /api/auth/login` (JSON `{username,password}`, lokaal), `GET /api/auth/callback` (Entra redirect_uri), `POST /api/auth/logout`, `GET /api/auth/me`. Deze zijn altijd publiek.
- Nieuwe Entra-gebruiker (sub onbekend): automatisch aanmaken met rol `AUTH_ENTRA_DEFAULT_ROLE` (default `viewer`); beheer past de rol later aan.
- Gating: bij `AUTH_REQUIRED=1` vereist `search` `require_role("admin","analist","viewer")`; `search_export` en batch vereisen `require_role("admin","analist")`; audit-log admin-only (rol `admin` óf `AUDIT_ADMIN_TOKEN`).
- Audit (Fase 1): `user`-kolom gevuld uit de sessie (provider-agnostisch); anoniem = `null`.
- Watchlists (Fase 4): `owner` = `user_id` bij ingelogd, anders cookie-key.
- UI-taal Nederlands; identifiers Engels. Geen code-commentaar tenzij niet-voor-de-hand liggend.
- STAGE nooit via `git add .`; alleen eigen bestanden. Testsuite: `.venv/bin/python -m pytest -v`.

### Task 1: auth-module (lokaal + sessie)

**Files:**
- Modify: `requirements.txt` (bcrypt, itsdangerous, authlib)
- Create: `app/auth.py`
- Test: `tests/test_auth.py`

**Interfaces:**
- Produces:
  - `default_auth_db() -> Path` — `AUTH_DB` of `data/auth.sqlite`; `init_auth_db(db_path)` — schema (idempotent).
  - `hash_password(password) -> str` (bcrypt); `verify_password(password, hash) -> bool`.
  - `create_user(db_path, username, password=None, role="viewer", idp=None, idp_subject=None) -> dict` (uniekheid per username én idp_subject; ValueError bij conflict/ongeldige rol).
  - `find_by_credentials(db_path, username, password) -> dict | None` (lokale login).
  - `find_or_create_idp_user(db_path, idp, idp_subject, default_role="viewer") -> dict`.
  - `create_session(user: dict, secret, max_age=43200) -> str`; `verify_session(token, secret) -> dict | None`.
  - `current_user(request, db_path, secret) -> dict | None`.

**Tests:** hashen/verifiëren; create_user lokaal + IdP (conflicten); find_by_credentials; find_or_create_idp_user (bestaand/nieuw); session round-trip + verlopen/geknoeid; current_user uit request.

### Task 2: Entra-provider (OIDC)

**Files:**
- Modify: `app/auth.py`
- Test: `tests/test_auth.py`

**Interfaces:**
- Produces:
  - `entra_config() -> dict | None` — uit env (`AUTH_ENTRA_ENABLED` etc.); `None` als uitgeschakeld; `issuer = https://login.microsoftonline.com/{tenant}/v2.0`; discovery via `{issuer}/.well-known/openid-configuration`.
  - `entra_client(config) -> authlib.integrations.httpx_client.AsyncOAuth2Client` (client_id/secret, PKCE-support).
  - `entra_authorize_url(client) -> (url, code_verifier, state)` — code_verifier/challenge (PKCE) + state (itsdangerous `URLSafeTimedSerializer`, korte TTL).
  - `entra_exchange(client, code, code_verifier, state_secret) -> dict` — token + userinfo; retourneert `{sub, preferred_username, email}`.
  - Claim-mapping: `idp_subject = sub`; `username = preferred_username or email or sub`.

**Tests:** config parsing (aan/uit + validatie-fout bij incomplete config); authorize-url + PKCE-verifier; exchange met gemockte Entra-discovery/token/userinfo (httpx mock) → sub/preferred_username; state-verificatie (ongeldig/verlopen → 400).

### Task 3: endpoints + gating

**Files:**
- Modify: `app/main.py`
- Test: `tests/test_main.py`

**Interfaces:**
- Consumes: `app.auth`.
- Produces:
  - `AUTH_SECRET`/`AUTH_DB`/`AUTH_REQUIRED`/`AUTH_ENTRA_*` uit env; validatie bij startup.
  - `get_current_user(request)` / `require_role(*roles)` dependencies.
  - `GET /api/auth/login`: Entra-enabled → `RedirectResponse` naar Entra (PKCE + state); anders 200/JSON (UI toont formulier). `POST /api/auth/login` (lokaal) → set-cookie. `GET /api/auth/callback` → code exchange + set-cookie + redirect naar `/`. `POST /api/auth/logout` → clear-cookie. `GET /api/auth/me`.
  - `POST /api/auth/users` (admin only): lokale gebruiker of Entra-toewijzing (`{username, password?, role, idp_subject?}`).
  - Gating (bij `AUTH_REQUIRED=1`) + audit-`user`-invulling.

**Tests:** lokale login (set-cookie/me/logout); Entra-flow met gemockte discovery+token+userinfo → set-cookie; state-fouten; require_role 401/403; AUTH_REQUIRED-gating; users-endpoint admin-only; audit-event `user` gevuld bij login en `None` bij anoniem.

**Verificatie:** `node --check`, volledige suite groen, handmatige test (lokaal login → audit `user`; IdP-flow indien een IdP beschikbaar is).

## Self-Review

**Spec-cover:** eigen login én Microsoft Entra ID (OIDC v2.0 + PKCE), eigen sessie-cookie na succesvolle auth (provider-agnostisch), rollen, `AUTH_REQUIRED`-gating, audit-`user`, watchlist-`owner`. IdP bewust beperkt tot Entra (andere providers niet ondersteund in v1). **Placeholders:** geen. **Consistentie:** `authenticate`-pad (lokaal vs Entra) mondt in beide gevallen uit in dezelfde `session`-cookie + `current_user`; `require_role`/audit gebruiken alleen de sessie. **Uitbreiding (later):** rol uit Entra-app-roles/groepen, andere IdP's (Keycloak/Google), webauthn/passkeys.
